# Предварительная версия: повседневное использование

Ветка: feat/daily-reliability. Студенческая версия не заменяется автоматически.

## Пять направлений
1. Расписание: сохранённый снимок при ошибке загрузки, история различий (включая циклы), отдельные даты загрузки и происхождения данных; текст обращения из карточки занятия.
2. Данные: экспорт/дополняющее восстановление профиля, ДЗ, преподавателей, файлов, личных событий, ПЗ и локальных обращений. До 80 МБ. Совпадающие ID сохраняют текущую запись. При ошибке между базами уже добавленные записи сохраняются, повторная попытка не дублирует ID. Обновление веб-приложения требует явного принятия. Для будущего APK добавлена проверка опубликованного android-release.json; старый установленный APK этот новый код ещё не содержит. Перед следующим Android-релизом versionCode и version нужно согласованно обновить в manifest и release-android.yml.
3. Каждый день: карта и материалы из занятия, карта ближайшей пары, сохранение вида и даты календаря в текущей сессии.
4. Адреса: группа / курс / справочник; предметы, связанные с адресом; неоднозначные сокращения не превращаются в предполагаемый маршрут. Входы в корпуса без подтверждения не добавляются.
5. Качество: регрессионные тесты копии и повторного восстановления, различий расписания, неоднозначных адресов и принятия обновления. QA публикует архив предварительной веб-версии с SHA-256 только после успешных проверок.

## Проверка перед массовым выпуском
- Полный npm run qa на окончательном коммите и успешный CI.
- Проверить экспорт и восстановление на другом тестовом профиле с реальным файлом, отключение сети, открытый черновик при обновлении.
- Отдельно провести испытания на физическом слабом Android и планшете; изменение ширины браузера не является проверкой производительности устройства.
- Проверить новый APK отдельно: веб-обновление не заменяет встроенные ресурсы установленного APK. Текущий подписанный APK — 3.2.0.
- Уточнения входов и неоднозначных сокращений добавлять только со ссылкой на подтверждённый источник.

## Пробный выпуск и откат
Архив web-preview-<commit> доступен в успешном QA workflow. Размещать пробную версию на отдельном адресе, не в подпапке основного сайта с тем же origin: localStorage привязан к origin и общий для подпапок. Добровольцы сначала сохраняют резервную копию.
При регрессии откатить коммит приложения и пересобрать с новым buildId, сохранив актуальные подтверждённые данные расписания. Не очищать localStorage и базы материалов, ПЗ или обращений. Предыдущие версии могут не понимать новые функции: перенос обеспечивается резервной копией, а не удалением приложения. Массовую публикацию выполнять только после проверки окончательного артефакта.
